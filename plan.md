### Важно знать

- Лучше договориться на каком языке будут коммиты.
- Лучше всего использовать правильно коммиты.
  - В идеале лучше всего делать один коммит - одно изменение.
  - В идеале лучше всего оформлять коммиты по списку ниже.

### 📝 Основные типы коммитов (Conventional Commits)

| Тип | Когда использовать | Пример |
| :--- | :--- | :--- |
| **feat** | Добавление новой функциональности (фичи) | `feat: добавить валидацию email в форме` |
| **fix** | Исправление ошибки (бага) | `fix: исправить вылет при нажатии на кнопку` |
| **docs** | Изменения в документации (README, комментарии в коде) | `docs: обновить инструкцию по установке Java` |
| **style** | Правки оформления кода (пробелы, отступы), не влияющие на логику | `style: поправить отступы в App.js` |
| **refactor** | Изменение кода ради его чистоты или структуры (не фича и не баг) | `refactor: вынести логику API в отдельный сервис` |
| **perf** | Изменения для повышения производительности (скорости работы) | `perf: ускорить рендеринг списка товаров` |
| **test** | Добавление или исправление тестов | `test: добавить тесты для системы сохранений` |
| **build** | Изменения, влияющие на сборку или зависимости (npm, maven, gradle) | `build: обновить версию react-router` |
| **ci** | Настройка автоматизации (GitHub Actions, скрипты развертывания) | `ci: настроить авто-деплой на хостинг` |
| **chore** | Прочие мелкие задачи (правка .gitignore, удаление мусора) | `chore: добавить папку /temp в игнор` |
| **revert** | Отмена (откат) предыдущего коммита | `revert: отменить изменения в навигации` |
